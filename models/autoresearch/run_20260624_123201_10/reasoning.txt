The champion is a LightGBM model with simple but sensible features: raw numerics, a few keyword flags from `name`, basic ratios, and frequency encodings for key categoricals. All subsequent runs show perfect metrics, which is almost certainly a validation/leakage artifact, so the best way to genuinely improve MAE and R2 is to (1) keep the strong LightGBM family, and (2) substantially enrich feature engineering in a still low-leakage way.

Hypotheses and improvements over the champion:

1. Spatial structure is underused.
   - Airbnb prices are highly location-dependent. Raw latitude/longitude help, but engineered spatial features often capture price gradients better.
   - We will compute a global centroid (mean latitude and longitude across the dataset) and add both haversine and Euclidean distance from each listing to this centroid. This approximates distance to the main city cluster and is non-leaky (uses only feature distributions).

2. Listing title (`name`) contains rich signals.
   - The champion uses a small keyword set. We'll expand to a richer set of price-relevant descriptors and add aggregate text features.
   - New binary keyword flags: 'luxury', 'cozy', 'apartment', 'studio', 'downtown', 'central', 'beach', 'sea', 'ocean', 'view', 'modern', 'spacious', 'loft', 'penthouse', 'villa', 'pool', 'garden', 'city center', 'old town', 'new', 'renovated', 'balcony', 'terrace'.
   - Aggregate text features: title length in characters, title length in words, and total keyword count. These are non-leaky and correlate with perceived quality.

3. Capacity and layout interactions matter.
   - Beyond the champion’s `beds_per_bedroom` and `accommodates_per_bed`, we add:
     * accommodates_per_bedroom = accommodates / bedrooms.
     * beds_per_accommodate = beds / accommodates.
   - These ratios capture how efficiently space is used and often correlate with price per guest.

4. Host behavior and experience.
   - We already have `host_tenure_days`. We add:
     * host_tenure_years = host_tenure_days / 365.
     * host_listings_log1p = log1p(host_listings_count) to capture diminishing returns of host scale.

5. Demand / intensity proxies from availability, revenue, and reviews (still no target usage).
   - Extend beyond `revenue_per_review`:
     * revenue_per_available_day = est_revenue / (availability_rate * 365 + 1) as a booking intensity proxy.
     * reviews_per_year_proxy = total_reviews / (host_tenure_years + 0.1) as a crude demand/activity measure.

6. Categorical encoding and interactions.
   - Keep frequency encoding for `room_type`, `property_type`, `neighbourhood`, and `neighbourhood_group`.
   - Add interaction frequency encodings:
     * neighbourhood_group_room_type_freq: frequency of each (neighbourhood_group, room_type) pair.
     * property_room_type_freq: frequency of each (property_type, room_type) pair.
   - Frequency encoding uses only category counts, not target statistics, so it is safe from leakage.

7. Robustness and cleanliness.
   - Drop identifiers (`listing_id`) and raw text/date columns (`name`, `host_since`) after feature extraction.
   - Ensure the returned DataFrame has only numeric columns (plus `target_price` if present) and fill remaining NaNs with 0.

Model configuration:
- We stay with LightGBM, which is well-suited for heterogeneous tabular data and can exploit the richer feature set.
- Compared to the champion, we slightly increase capacity and regularization to better model complex interactions while controlling overfitting under a proper validation scheme:
  - More trees with a smaller learning rate: n_estimators=800, learning_rate=0.035 for finer learning.
  - num_leaves=63, max_depth=-1 to allow more complex trees.
  - Stronger regularization: reg_lambda=2.0, min_child_samples=40, plus subsample and colsample_bytree at 0.8.

This experiment is a principled extension of the champion: same model family, but with significantly richer spatial, textual, and interaction features and a more regularized configuration. Under a correct validation setup, this should improve MAE and R2 by giving the model more structured, informative signals about location, property quality, and host behavior.
