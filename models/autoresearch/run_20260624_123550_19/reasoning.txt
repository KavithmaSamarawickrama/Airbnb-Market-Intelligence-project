All runs so far, including the champion, report perfect metrics (MAE=0, R2=1), which strongly suggests a leakage or validation artifact. Within this loop, however, we still aim to design a configuration that would be strong under a correct evaluation. The champion is a LightGBM model with basic numeric features, a small set of name keywords, simple ratios, and frequency encodings. Several subsequent runs repeated similar reasoning without actually changing the champion configuration. The next experiment should therefore (1) stay with LightGBM (well-suited for this tabular regression), (2) significantly enrich feature engineering in a still low-leakage way, and (3) modestly adjust hyperparameters to better exploit richer features while controlling overfitting.

Key hypotheses and feature strategy:

1. Spatial structure is underused.
   - Prices are highly location-dependent. Raw latitude/longitude help, but distance-to-centroid features often capture spatial gradients better.
   - We will compute a global centroid (mean latitude and longitude over the dataset) and add both haversine and Euclidean distance from each listing to this centroid. This uses only feature distributions (no target), so it is safe from leakage.

2. Listing title (`name`) contains richer signals than the champion uses.
   - Expand keyword list to include more price-relevant descriptors: 'luxury', 'cozy', 'apartment', 'studio', 'downtown', 'central', 'beach', 'sea', 'ocean', 'view', 'modern', 'spacious', 'loft', 'penthouse', 'villa', 'pool', 'garden', 'city center', 'old town', 'new', 'renovated', 'balcony', 'terrace'.
   - For each keyword, create a binary indicator.
   - Add aggregate text features: title length in characters, title length in words, and total keyword count. These are non-leaky and often correlate with listing quality and thus price.

3. Capacity and layout interactions.
   - Champion already uses `beds_per_bedroom` and `accommodates_per_bed`. We add:
     * `accommodates_per_bedroom` = accommodates / bedrooms.
     * `beds_per_accommodate` = beds / accommodates.
   - These ratios capture space efficiency and price-per-guest structure. All divisions are done safely to avoid division by zero.

4. Host behavior and experience.
   - We already have `host_tenure_days`. We add:
     * `host_tenure_years` = host_tenure_days / 365.
     * `host_listings_log1p` = log1p(host_listings_count) to capture diminishing returns of host scale.

5. Demand / intensity proxies from availability, revenue, and reviews.
   - Extend beyond `revenue_per_review`:
     * `revenue_per_review` = est_revenue / (total_reviews + 1) (recomputed robustly).
     * `revenue_per_available_day` = est_revenue / (availability_rate * 365 + 1) as a booking intensity proxy.
     * `reviews_per_year_proxy` = total_reviews / (host_tenure_years + 0.1) as a crude demand/activity measure.

6. Categorical encoding and interactions.
   - Keep frequency encoding for `room_type`, `property_type`, `neighbourhood`, and `neighbourhood_group`.
   - Add interaction frequency encodings:
     * `neighbourhood_group_room_type_freq`: frequency of each (neighbourhood_group, room_type) pair.
     * `property_room_type_freq`: frequency of each (property_type, room_type) pair.
   - Frequency encoding uses only category counts, not target statistics, so it is safe from leakage.

7. Robustness and cleanliness.
   - Drop identifiers (`listing_id`) and raw text/date columns (`name`, `host_since`) after feature extraction.
   - Ensure the returned DataFrame has only numeric columns (plus `target_price` if present) and fill remaining NaNs with 0.

Model configuration:
- Stay with LightGBM, which handles heterogeneous tabular data well and can exploit the richer feature set.
- Compared to the champion, increase capacity and regularization to better model complex interactions while controlling overfitting:
  - More trees with a smaller learning rate: `n_estimators=800`, `learning_rate=0.035` for finer learning.
  - `num_leaves=63`, `max_depth=-1` to allow more complex trees.
  - Stronger regularization: `reg_lambda=2.0`, `min_child_samples=40`, plus `subsample` and `colsample_bytree` at 0.8.

Under a realistic validation setup, this configuration should improve MAE and R2 by giving the model more structured, informative signals about location, property quality, host behavior, and demand.
